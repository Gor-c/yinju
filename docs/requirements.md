# 知识库管理系统需求说明

版本：0.3（增加 Agent 只读工具循环、SSE 流式回答与运行追踪）  
状态：需求基线；标注“待实现”的内容不能视为已交付能力。

## 1. 项目目标

建设一套可独立部署的知识库管理系统，管理项目、审核记录、隐患和档案文档，并为文档提供语义检索能力。系统由 Go 后端、Vue 3 前端、关系数据库、可替换的向量存储组件及模型服务组成。系统本身还提供 MCP 服务，供 WorkBuddy 等外部 Agent 作为连接器调用。

核心流程：

1. 管理人员选择项目和文档类型并上传档案。
2. 服务端提取文档文本，按配置切块，调用 BGE-M3 生成 1024 维向量并持久化。
3. 用户查看项目资料、隐患、审核历史和档案索引概况。
4. Agent 或 MCP 客户端按项目范围检索档案片段，并据此组织回答或后续工作流。

## 2. 用户与使用场景

| 角色 | 主要场景 |
| --- | --- |
| 档案管理员 | 上传项目档案、查看索引任务状态、确认资料是否可检索 |
| 业务人员 | 查看项目档案概况、隐患与审核历史，定位档案依据 |
| 外部 Agent / WorkBuddy | 通过 MCP 列出项目、读取项目信息、查询隐患/审核历史和档案片段 |
| 系统运维人员 | 配置数据库、模型 API、上传目录、MCP 凭据，部署和监控服务 |

## 3. 功能需求

### 3.1 项目与业务档案

- 项目具有稳定唯一的 `unit_id`，至少记录名称、项目分类和行业。
- 项目分类与行业可新建、可修改，并提供已有取值作为候选。
- 项目可绑定一个 Agent 和若干技能，用于对话时自动套用。
- 支持上传 Agent 与技能定义（JSON 或 Markdown），上传项覆盖同 id 的内置项，并可删除；入口位于「设置 > Agent 与技能」，与模型服务、联网搜索同列。
- 可按名称浏览项目，并打开项目详情。
- 项目详情应呈现项目基础资料、档案索引数量、隐患清单和审核历史。
- 隐患支持按状态过滤；审核记录按时间倒序展示。
- 审核 JSON 导入应有 API 契约，可将审核结果写入结构化表并供画像、隐患和 MCP 工具使用。

### 3.2 文档上传与索引

- 上传必须指定 `unit_id` 或 `unit_name`（二选一）、`doc_type` 和文件；`unit_id` 不存在返回 404，`unit_name` 未匹配到项目时自动创建（生成 `unit-<hex>` 形式的 `unit_id`）。
- 支持格式：TXT、Markdown、JSON、HTML、CSV、DOCX；PDF 需要部署 `pdftotext`。扫描件 OCR 不在当前范围。
- 上传按扩展名白名单和大小上限（默认 50 MB，`MAX_UPLOAD_MB`）校验。
- 上传文件按项目分目录保存；原文件名作为检索出处元数据。
- 上传成功立即返回任务 ID。任务状态包括 `queued`、`running`、`done`、`failed`，提供进度、说明和写入 chunk 数。
- 任务状态持久化到 `index_jobs`；服务启动时仅恢复超时阈值外的陈旧 `running` 任务；异常退出最多恢复 3 次，索引处理错误直接标记 `failed`。
- 默认中文字符切块参数为 1800 字符、重叠 240 字符；实现可按后续文档解析方案升级为按段落/标题切分。
- embedding 使用 OpenAI-compatible `/embeddings` 接口，默认模型 `BAAI/bge-m3`、维度 1024；请求分批，每批默认 16 段。
- 同一项目、文件名、chunk 序号再次入库时更新原记录，避免重复行；新版本 chunk 数变少时删除尾部多余记录。
- `documents` 记录文档版本、chunk 数和源文件路径；提供按 `unit_id` + `filename` 删除向量与源文件的接口，用于改名或撤档清理。
- 项目详情页支持「原文预览」和「提取文本」两种查看方式：PDF、Word（DOCX）、Excel（XLS/XLSX/CSV）、Markdown 与文本在弹窗内直接渲染；不支持的格式可下载原件。文本预览支持查找、匹配定位和复制。
- embedding 模型或维度变化必须重建或迁移全部索引，并保证旧向量不会与新模型向量混用。
- 空文档、解析失败、模型服务失败和向量库失败必须使任务进入 `failed` 并保留可诊断错误信息。

### 3.3 项目画像与 Agent 对话

- 画像页显示项目基础信息、审核数、未关闭隐患数、已索引 chunk 数。
- 风险评分、风险档位、业务标签等需以审核数据和正式画像规则为依据；当前原型不计算附件示例中的评分，需在接入并确认线 A 规则后实现。
- 前端提供 Agent 对话入口，支持选择项目、专家、技能并查看回答；回答以流式方式展示，并显示检索步骤。
- 选择项目时，内置 Agent 使用只读工具循环（项目画像、隐患、审核历史、向量检索），最多 `AGENT_MAX_STEPS` 步；项目范围由服务端固定，模型不能跨项目查询。
- 对话页选择项目后自动带出项目绑定的 Agent、技能与工具；技能通过 `tools` 声明所需工具，Agent 的工具声明作为上限，两者都未声明时启用全部只读工具。
- Agent 回答应优先引用所选项目检索到的档案片段；证据不足时应说明，不得伪造档案结论。
- 外部 MCP connector 的定义可展示/配置；内置 Agent 是否主动调用外部 MCP 服务属于待实现能力，不能将仅展示 connector 配置当作工具调用完成。

### 3.4 MCP / WorkBuddy 接入

- 系统提供 Streamable HTTP MCP endpoint：`POST /mcp`。
- MCP 提供只读工具：`list_units`、`get_unit_profile`、`query_hazards`、`audit_history`、`vector_search`。
- 所有项目级工具必须显式提供 `unit_id`；检索仅返回该项目范围内资料。
- MCP 必须使用 Bearer token；未配置 token 时拒绝服务，错误 token 返回 401。生产远程访问必须使用 HTTPS。
- WorkBuddy connector 包应包含 connector metadata、MCP endpoint 配置、token 输入定义、图标和领域 Skill。安装时替换部署地址并录入服务端配置的 token。
- MCP 工具默认只读，不得通过工具暗中修改项目或审核数据。

### 3.5 运维与部署

- Go 服务提供 `/health`，说明进程和数据库配置状态。
- 前端生产构建由 Go 服务托管；开发期使用 Vite proxy。
- 可通过环境变量设置数据库、向量 provider、模型服务、上传目录、MCP token 和 Agent 配置。
- 支持 Ubuntu systemd 部署；密钥放在权限受限的环境文件中，不提交到仓库。

## 4. 非功能需求

- **边界清晰**：业务/API 不直接依赖某一家向量数据库；向量持久化通过 `vectorstore.Store` 接口。
- **可替换性**：pgvector 和 Chroma v2 REST adapter 均可用；其他 provider 以独立 adapter 接入，需支持 upsert、按 unit_id 过滤的相似度检索和计数。
- **可恢复性**：结构化数据、任务状态和 Agent 运行追踪持久化在 PostgreSQL；向量持久化由 Chroma 或 pgvector 提供。上传任务启动时只恢复超时阈值外的陈旧 `running`；异常退出最多恢复 3 次，索引处理错误直接失败。目前没有自动迁移/跨库事务。
- **安全性**：MCP 使用常量时间 token 比较；外网入口使用 TLS、限流和访问控制。v0.1 单机原型没有登录、角色权限或细粒度项目授权。内置 Agent 只暴露项目级只读工具，`unit_id` 由服务端固定。
- **可观测性**：结构化日志统一写入 `app.log`、`access.log`、`error.log` 并按大小轮转；HTTP 响应带 `X-Request-ID`，日志记录 request/job/run ID、阶段、耗时和失败原因；`agent_runs`/`agent_steps` 记录 Agent 工具调用与 token 用量；不得记录 API key、MCP token 或完整敏感档案内容。
- **数据保护**：按部署项目的数据分级与保留策略配置备份、上传目录权限、删除和归档策略；目前没有自动清理、加密静态文件或审计操作台。

## 6. 验收标准

1. 配置 PostgreSQL、所选向量库（Chroma 或 pgvector）、模型服务和 Go 服务后，健康检查与项目列表可用。
2. 对项目上传支持的文档后，任务状态可轮询到完成；所选向量库中能按项目过滤检索到文档 chunk，向量维度为 1024。仅 pgvector 模式检查 `doc_chunks` 表。
3. 使用同一项目的问题进行检索时，只返回该项目文档；结果包含文件名和片段，可作为引用依据。
4. 项目详情正确显示基础信息、审核数、开放隐患数和索引 chunk 数。
5. MCP 客户端通过 Bearer token 可发现并调用五个只读工具；无 token/错误 token 被拒绝。
6. WorkBuddy connector 导入后可以配置服务地址与 token，并成功调用 MCP 工具。
7. 选择项目进行 Agent 对话时，SSE 能收到 `tool_call`/`tool_result`、文本增量和 `run_completed`；`agent_runs` 状态为 `completed`，工具明细写入 `agent_steps`；模型不能通过工具查询其他项目。
8. 构建检查：`go test ./...`、`go vet ./...`、前端 `pnpm build` 通过；已有切块、解析、上传校验、Agent Loop、流式解析、MCP 与 Chroma adapter 单元测试，数据库查询和真实模型调用仍需集成验收。

## 7. 决策与待确认项

- 生产数据库连接地址、连接用户、备份方案及 `vector` 扩展可用性。
- BGE-M3 与 LLM 的真实 API key、限额、请求超时和数据出境要求。
- 审核 JSON 的真实样例和评分/标签计算规则。
- 最大文件大小、允许 MIME/扩展名、存储保留期和删除策略。
- 是否需要项目级用户授权，以及 MCP token 的签发、轮换和吊销方式。
- Chroma 生产部署形态（本地/服务端）、集合命名与 pgvector/Chroma 数据迁移策略。
- WorkBuddy 生产租户的 connector 导入流程及兼容协议版本。

04 · 检索五层与拒答

每一层都会丢东西，失败表现却都是「答不上来」。所以每层都要计数，才能知道是哪一层掐掉的。

查询
知识库 → doc_id 集合，先过滤再检索
↓
① 身份校验
匹配 / 不匹配拒绝 / 未登记放行+告警
↓ 分两路并行召回
② 向量召回 K=30
稠密语义
＋
② 关键词召回 K=30
pg_trgm，型号与错误码
↓ 单路失败自动降级，两路都失败才算检索失败
③ RRF 融合
只看排名，取前 20
→
④ 精排 + 分数阈值
cross-encoder，低于 min_score 丢弃
→
⑤ 覆盖率闸门
二元组覆盖率 < min_overlap 丢弃
↓
注入上下文
带 [n] 编号与文件名
／
拒答
no_evidence=true，不调模型
每次检索落一行计数：doc_count / vector_hits / keyword_hits / fused / reranked / kept / no_evidence / degraded / duration_ms。
  • reranked=0 → 精排阈值问题；reranked>0 而 kept=0 → 覆盖率闸门问题。
  • 只看「命中率」时，这两种情况长得一模一样，调参必然是盲改。

05 · 记忆分层与注入顺序

记忆解决「别忘了用户说过什么」，它不参与检索，也不许冒充证据。

L1 工作记忆
最近 20 条原文，滑出即丢失
→
L2 滚动摘要
summary_upto 水位线，只压已滑出部分
→
L3 原子事实
topic + active，同主题新说法取代旧说法
↓ 一次调用同时产出摘要与事实，失败只记日志、不阻塞回答
注入 position 1
人设
→
2 知识库与工具
本次可用清单
→
3 工具规则 1–10
硬约束，不可被上传定义覆盖
→
4 记忆块
只用于理解上下文
一条硬规则：摘要与事实不得作为答案依据，不得出现在引用编号里。允许记忆充当证据，等于让上一轮的转述变成这一轮的证据，还附带一个看起来合法的编号。

06 · 知识沉淀闭环

问答的产物不直接回写知识库：先成为草稿，人工采纳后才进入索引。模型输出不会自我强化。

↓ 旁路：这两条永远不进入索引
忽略
dismissed
｜
整理（每小时·满 8 条）
聚成主题笔记 → 新草稿 pending，原问答标 merged
↓ 主链：只有采纳这一条会进入知识库
采纳
生成 draft-<id>-<kind>.md
→
index_jobs
doc_type=问答沉淀
→
切块 · 嵌入 · 大纲
与普通上传完全一致
→
可被检索

证据不自我强化：沉淀时过滤 doc_type=问答沉淀 的引用，否则问答 → 沉淀 → 再检索 → 再沉淀会逐层放大模型误差；若过滤后没有来源，就不产生新草稿，闭环自然终止。

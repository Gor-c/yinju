# 实例配置（数据库 / 向量库 / 运行目录）

页面位置：**设置 → 部署 → 实例配置**（`/settings/instance`）

## 为什么单独做一个页面

这些值和「检索参数」「品牌」不同，它们决定进程**怎么启动**：连哪个数据库、用哪种向量库、监听哪个端口、文件放哪个目录。改了必须重启。

但它们又必须能在页面上改，因为最常见的事故是：数据库地址写错了，服务起不来，只能 ssh 到服务器上翻文件。所以这个页面有一条硬性设计约束——

> **它的所有接口都不依赖数据库连接。**

`GET /api/v1/instance/config` 只读文件和环境变量，不查库。所以即使 `PG_DSN` 改错、重启后连不上 PG，这个页面依然能打开、能改回去。这不是顺手做的好意，而是整个功能成立的前提。

## 优先级

```
1. 进程环境变量（systemd / docker -e 注入）
2. data/instance.env        ← 本页面写入
3. .env                     ← 人工维护
4. 代码默认值
```

`loadEnvFile` 对已存在的变量会跳过，所以**先加载的赢**。`cmd/server/main.go` 里先加载 `instance.env`，再加载 `.env`。

这条链解释了两个容易踩的现象：

- **在 `.env` 里改了值，但页面上保存过，所以没生效。** 页面上保存过的键都在 `instance.env` 里，优先级更高。要么在页面上改，要么删掉 `instance.env` 里那一行。
- **在页面上改了值，重启后还是旧值。** 大概率是 systemd 或容器注入了同名环境变量。页面会把它标成「环境变量」并禁用输入框——这种情况只能改部署配置。

## 文件长什么样

```sh
# 由「设置 → 实例配置」写入，也可以手工编辑。
# 优先级：外部环境变量 > 本文件 > .env > 代码默认值。
# 改动需要重启服务才生效。
PG_DSN='postgresql://postgres:***@127.0.0.1:5433/fire_archive?sslmode=disable'
VECTOR_STORE='chroma'
CHROMA_URL='http://127.0.0.1:8000'
CHROMA_TENANT='default_tenant'
CHROMA_DATABASE='default_database'
CHROMA_COLLECTION='fire_archive'
LISTEN_ADDR='127.0.0.1:8081'
UPLOAD_DIR='./data/uploads'
BRAND_DIR='./data/brand'
```

路径由 `INSTANCE_ENV_FILE` 指定，默认 `./data/instance.env`。文件权限 `0600`，写入是「临时文件 + rename」，避免写到一半被重启留下半截配置。

## 密码怎么处理

- **永远不回传明文。** 页面只拿到 `password_set: true/false` 和一个脱敏 DSN（`postgresql://postgres:***@…`）。
- **密码框留空 = 不修改。** 这是唯一不会把密码清空的语义。后端用 `passwordFromDSN` 从当前生效的 DSN 里把原密码取回来再拼新 DSN。
- **密码含特殊字符也安全。** `@ : / ? #` 由 `url.UserPassword` 编码；这条有单测覆盖（`internal/app/instance_test.go` 的 `TestDSNRoundTrip`）。

## 改错了怎么办

保存前会实测一次数据库连接（4 秒超时），连不上直接拒绝写入。错误信息是人话，比如「连接被拒绝，检查主机与端口，以及数据库是否已启动」。

确实需要「先写配置、后启数据库」时，可以在提示框里选「仍然保存」。这条路的后果是：重启后服务连不上 PG，但——

1. 打开 `/settings/instance`（页面本身不查库，能打开）
2. 点「回滚上一版」（用 `instance.env.bak` 覆盖）
3. 重启

备份是**每次保存前**自动做的，所以它始终是「上一个已知状态」，不是「最初状态」。回滚时还会把当前这版留成 `instance.env.prev`——回滚本身也可能是错的。

如果连页面都打不开（比如端口写错、进程没起来），只能到服务器上手工处理：

```sh
# 看一眼写坏了什么
cat data/instance.env
# 恢复上一版
mv data/instance.env.bak data/instance.env
# 或者整个删掉，退回 .env
rm data/instance.env
```

## 边界与已知限制

**多实例部署。** 配置在共享的 `data/instance.env` 里没问题，但 `UPLOAD_DIR` 和 `BRAND_DIR` 必须挂共享卷，否则每个实例看到的上传文件和图标不一样。另外页面提示的「重启」只对当前进程有效，滚动更新时请确认所有实例都拿到新配置。

**没有加密。** 文件是明文，权限 `0600`。如果宿主机磁盘本身不加密，密码在磁盘上是可见的。这与 `.env` 的现状一致，没有变好也没有变差。

**没有鉴权。** 这个接口和项目里其它 API 一样，默认不校验身份。如果服务需要暴露到公网，应该在反向代理层加认证，或者设置 `API_TOKEN`。**实例配置接口会返回数据库主机、库名、用户名**，属于敏感信息，别把它直接放到公网。

**端口改了但反向代理没改。** 页面无法感知反向代理，`LISTEN_ADDR` 改成 `0.0.0.0:9000` 之后，nginx / 系统防火墙都要同步改。页面在字段下方给了提示，但没有校验。

## 与本页无关的配置

以下仍在 `.env`，没有搬到页面上，因为它们要么属于「构建期」、要么改动风险大于收益：

| 键 | 为什么留在 .env |
|---|---|
| `LOG_*` | 日志系统在读取配置之前就已初始化，页面改不了已经打开的文件句柄 |
| `LLM_*` / `EMBED_*` | 已经在「设置 → 模型服务」里，无需重复 |
| `WEB_SEARCH_*` | 已经在「设置 → 联网搜索」里 |
| `MCP_AUTH_TOKEN` | 密钥类，轮换应走部署流程，不该在页面上点 |
| `MAX_UPLOAD_MB` / `INDEX_TIMEOUT_MINUTES` | 可迁移到页面，但影响面小，暂未做 |
